# المعمارية — Architecture

النظام كامل من أربع طبقات. المستودع يحتوي الطبقة 1 و2، ويضم الطبقة 3 و4 تحت
`stack/` و`config/`.

```
                   جهاز آخر / متصفح
                          │ HTTPS (نفق) أو LAN
                          ▼
        ┌─────────────────────────────────────────┐
        │ cloudflared  (quick or named tunnel)    │   الطبقة 2
        └──────────────────┬──────────────────────┘
                           │
   ┌───────────────────────┴───────────────────────┐
   │                dsh-stack (نظام)               │   الطبقة 3
   │  proxy → tunnel → harness، فحص جاهزية، إعادة  │
   │  تشغيل، watchdog، session-keeper              │
   └───────┬───────────────────────┬───────────────┘
           │                       │
           ▼                       ▼
  ┌─────────────────┐     ┌──────────────────────┐
  │ zen-relay :8901 │     │ dsh web :30141       │   الطبقة 1 و4
  │ pool + rotate   │◄────│ Harness (OpenAI API) │
  └────────┬────────┘     └──────────────────────┘
           │ rotating egress
           ▼
   opencode.ai/inference/openai/v1
```

## الطبقة 1 — المرحّل (`zen-router/`)

- يستمع على `127.0.0.1:8901` (قابل للتغيير بـ`HOST`/`PORT`).
- يبني pool من بروكسيات HTTP/SOCKS حرة، يفحص كل واحدة بطلب حقيقي، ويوزّع
  الطلبات عليها.
- يحمل بصمة `User-Agent` الخاصة بـOpenCode — بدونها ترفض الطبقة المجانية الطلب
  حتى لو كان الـIP نظيفاً.
- يحوّل أخطاء الـlane (429/403) إلى `503 zen_lane_blocked` قابل لإعادة المحاولة،
  فلا يرى العميل خطأ مصادقة.
- مصادقة واحدة: `Authorization: Bearer rly_…` (أو المفتاح مجرداً). كل المسارات
  تحت `/api` و`/v1` محمية؛ `/healthz` فقط مفتوح.

## الطبقة 2 — النفق

ثلاثة أنماط (`tunnel.mode` في `config.json`):

- `own` — Cloudflare quick tunnel: بلا حساب، لكن الاسم يتغيّر عند كل تشغيل.
- `named` — أمر ثابت من `namedCommand` واسم من `hostname`: نفق Cloudflare
  مُسمّى (يحتاج نطاقاً)، أو **Tailscale Funnel** (`tailscale funnel 30141` ←
  `https://<host>.<tailnet>.ts.net` — النمط المستخدم على هذا التثبيت).
- لا يُشترط النفق للاستخدام المحلي؛ بدونه يعمل كل شيء على نفس الجهاز.

## الطبقة 3 — المشرف (`stack/`)

`dsh-stack` يشغّل ثلاث مجموعات عمليات بترتيب تبعية صارم:

1. بوابة شبكة (TCP حقيقي إلى المزوّد، وليس `network-online.target`).
2. المرحّل، ثم فحص `/healthz` حتى `{"ok":true}`.
3. النفق، ثم استخراج اسم المضيف من مخرجاته.
4. الـHarness بـ`--trusted-host <tunnel host>`، ثم فحص `/`، ثم نشر رابط الدخول
   في `~/dsh-url.txt`.

إعادة تشغيل المرحّل توقف الـHarness أولاً وتعيده بعد جاهزية المرحّل، لأن turnاً
واحداً على مسار ميت يفسد الجلسة. التفاصيل الكاملة في `stack/README.md`.

## الطبقة 4 — الـHarness (`dsh`)

- يعرض واجهة ويب على `30141` مع مصادقة كوكي مرتبطة بالمضيف (30 يوماً).
- يتصل افتراضياً بالجسر `opencode-bridge` (‏`baseURL` على 8902) الذي يقود خادم
  OpenCode المحلي؛ مزوّد `opencode-zen` (المرحّل على 8901) يبقى مساراً ثانوياً.
  الربط في `cordis.patch.yml`.
- الـplugin `dsh-session-keeper` يستأنف الجلسات التي انقطع turnها بعد عطل.

## أين تُحفظ الحالة والأسرار

| المسار | المحتوى | يُرفع إلى Git؟ |
|---|---|---|
| `zen-router/settings.json` | إعدادات + `relay_api_key` | **لا** |
| `zen-router/lanes.json`, `burned.json` | حالة الـpool | لا |
| `~/.dsh/.credentials.yaml` | مفتاح المرحّل للـHarness | **لا** |
| `~/dsh-url.txt` | رابط الدخول مع توكن | **لا** |
| `~/.config/dsh-stack/config.json` | مسارات وأوامر | لا (يُنشأ محلياً) |

`.gitignore` في المستودع يمنع هذه الملفات.
